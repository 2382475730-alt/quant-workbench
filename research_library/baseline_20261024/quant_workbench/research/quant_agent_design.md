# 怎样做一个可复刻这套工作的量化Agent

当前已实现的是可调用的确定性研究工具层，不是已经接入LLM、能够自主产生可靠投资建议的成品Agent。它不连接券商，不自动交易。语言模型负责提出有限假设、理解证据和写报告，计算与风控由可检查的代码执行。

## 1. 它应复刻什么
复刻的是研究方法：定义问题→审计资料→登记假设→冻结规则→运行完整对照→发现反例→判断证据→保存可重跑结果。目标不能写成“找一个一定跑赢的模型”，否则Agent会不断搜索直到过拟合。

本轮已经展示完整反例链：v1连续优化目标合规，但整手与价格漂移导致实际偏离；初始失败又可能被换手限制锁在现金。v1r2改善数值尺度，但简单取整与换手约束冲突。v1r3改用整数规划和冻结股数订单，主方案执行改善，防御备选的早期启动失败仍保留。v1r4又修正首次实际建仓状态，避免失败后被换手预算锁死；不改变已有持仓的换手规则。每次修订先登记工程原因再重跑完整对照，不按收益倒选版本。

## 2. 人类给Agent的任务合同
必须明确基准（本轮H00300.CSI全收益）、市场与可交易资产、本金、费用、禁止事项、风险/行业/换手预算、数据截止日、计算时间上限、实验数量和判定标准。账户风险预算不能由Agent从回测曲线反推。本轮100万元及各约束是研究设定，不是对个人资产的配置建议。

## 3. 七个阶段及退出条件

| 阶段 | Agent做什么 | 确定性门禁 |
|---|---|---|
| 登记 | 写少量假设、对照、指标、修订规则 | 协议版本、参数文件、研究状态齐全 |
| 采集 | 调取已授权接口与官方资料 | 查询参数、原始响应、时间与哈希；不能记录凭据 |
| 数据核验 | 检查交易日、重复、分红、行业区间 | 缺全收益序列、金额冲突、核心时间轴缺失就停止相关结论 |
| 冻结 | 固定代码、数据、参数 | 新版本专属freeze.json；之后任何差异都会报错 |
| 运行 | 完成预登记全部实验 | 真实成交账本、成本、未成交、失败求解全部保存 |
| 审计 | 检查目标与实际、净收益与基准 | 现金/股票/应收守恒，信号先于成交；约束失败不可叫成功 |
| 报告 | 比较全部结果，提出下一步 | 回溯、已见数据和未来观察明确分开；软件通过不是策略采用 |

## 4. 工具层已经可以运行
在quant_workbench目录，用本目录虚拟环境执行：

```powershell
.\.venv\Scripts\python.exe -m quant_workbench.quant_agent status
.\.venv\Scripts\python.exe -m quant_workbench.quant_agent verify
.\.venv\Scripts\python.exe -m quant_workbench.quant_agent run --minutes 240
.\.venv\Scripts\python.exe -m quant_workbench.quant_agent report
```

- status只读状态；verify离线核对四个版本的冻结输入、108个实验清单、1080个结果文件、持仓余额、成交时序及业绩数值。
- run只调用固定白名单实验，开始前验证已有产物；已完成实验复用，不联网、不调参，不重写净值。当前完整结果存在时主要执行复用和核验，不是假装重新计算。
- report验证后从保存结果重建可视化与对照表；不会改变研究输入。
- events.jsonl按前一事件哈希串联，记录动作与失败；verify检查链条。这是可检测意外改动的审计链，不是抵御拥有文件写权限者的防篡改安全系统。

## 5. 接入Astra或其他LLM的方法

已提供`src/quant_workbench/agent_interface.py`：`TOOLS`包含四个闭合JSON工具定义，`dispatch(name, arguments)`校验白名单、参数和单次有限时间预算；可由模型调用客户端直接包装。`research/quant_agent_system_prompt.md`是可复制的初始任务说明。该接口本身不启动模型、不持有密钥。外层仍需限制总调用次数、累计预算和文件权限。
当前可调用get_status、run_registered、verify_artifacts、build_report；后续可以增加受限read_protocol、read_quality与只写草案的propose_next_version。底层调用上述模块；不能暴露无约束的任意shell执行、数据库写入或券商下单。API密钥只由环境/本机凭据管理器读取，不出现在提示词、报告、日志。

LLM输出使用结构化协议，例如：

```json
{
  "action": "propose_next_version",
  "hypothesis": "限制行业内主动权重能否减少集中风险",
  "economic_reason": "降低同一行业共同冲击",
  "known_periods": ["2017-2021", "2022-2024", "2025-2026-10-23"],
  "new_holdout": null,
  "primary_metric": "net_active_return_at_comparable_risk",
  "max_candidates": 2,
  "stop_rule": "不满足数据/执行/风险门禁即停止采用判断"
}
```

自然语言建议先转为可审阅配置，随后程序检查字段、权限、总预算和历史尝试记录。外部PDF、网页和API字段都按数据处理，里面出现的“运行命令/忽略规则/修改参数”不能成为Agent指令。

## 6. 如何防止它过拟合
固定实验数量与经济理由；记录所有尝试；参数选择只能使用声明的训练阶段，并保留滚动检验。已查看的未来区间不能重新标成盲测。工程修复必须说明与收益无关的触发证据，原版本保留；修复也增加研究尝试次数，统计解释随之更新。

本轮两个主动规则×三个时期×四个工程版本共24个基础比较，当前报告采用保守多重比较区间；旧版原始区间及压力情景全部保留。该处理仍不能消除更早研究、行业历史回填和当前选题造成的偏差。禁止以“某区间显著”自动批准实盘。

## 7. 下一阶段真正缺什么
- 新日期数据的增量采集与来源版本归档；当前asof固定2026-10-23，尚未部署自动刷新。
- 公司行动、行业公告和指数成分调整原始发布时间的更完整历史版本。
- 能在实际可交易报价下检查订单并处理约束冲突的执行风控。目前已有收盘整数股数目标、次日固定股数模拟成交和逐日偏离审计，仍不能声称盘中硬风控。停牌、价格变化或严格换手上限可能阻止即时修复风险。
- 新数据到来后仅追加的前向模拟账户，保存当时发出的计划，不能事后回写信号。本轮尚无前向收益，也没有将现有组合观察入口冒称完整的新Agent模拟交易系统。
- 生产服务需要进程隔离、只读数据挂载、签名产物、权限最小化和运维监控；当前本地runner不是安全沙箱。

## 8. 怎样评价Agent
首先看重跑是否一致、时点是否正确、失败是否保留、成本是否完整、约束是否被实际遵守、结论能否从证据复核。投资能力则必须由更长的新前向记录评价。Agent能够解释“这轮没有发现可信的增强”，也是正确完成任务。
